Your First App with Claude

You know your department's problem. Claude writes the code. This guide walks you from "I have an idea" to "my team is using it", one step at a time. You never need to type code.

You needClaudeThe Claude app on your laptop, signed in with your company account.
You needA company GitHub accountWhere your app's code is kept safely. IT sets this up.
You needA real problemSomething done today in Excel, on paper or in WhatsApp that wastes time.
    Step 1 · once per app

    Ask IT to create your app

    IT creates the empty app for you: its project on GitHub, its web address, its database and the staff login. You can't skip this, but it's one short message.

    Message to IT · fill in the brackets
    Hi IT, I'd like to build a small app with Claude.

Department: [e.g. Procurement]
What it does: [e.g. staff submit purchase requests, managers approve them]
Who will use it: [e.g. about 15 people in Procurement]
Sensitive information: [e.g. supplier prices / none]

Could you create the app and send me the GitHub link? Thanks!
    IT replies with a GitHub linkIt looks like github.com/Metrio-Group/your-app-name. Keep it. You need it in the next step.
    Step 2

    Open your app in Claude

    1. Open the Claude app and go to Code.
    2. Start a new session.
    3. Choose your app's project. If Claude asks for it, paste the GitHub link IT sent you.
    How you know it workedClaude reads the project's rules, then greets you and asks what you'd like to build. It follows the company's rules by itself, so you don't need to explain them.
    Can't see your project?Your GitHub account may not have access yet. Ask IT to add you to the app.
    Step 3

    Tell Claude what you need, in your own words

    Write it the way you'd explain it to a new colleague: your department, how it's done today, what's painful, and who will use it. English, Chinese or Malay are all fine.

    Too vague

    "Make me an inventory app."

    Clear

    "I'm from Site. We count materials on paper every Friday and often run out of cement. I want to record stock in and out, and see what's running low. 6 supervisors will use it on their phones."

    Five rules to keep you safe
    
      
    
        
    Never paste a password or keyNot in the chat, not in the app. If you did by accident, tell IT right away so they can change it. It's not your fault; reporting quickly is what matters.
    
        
    Use fake data when testingFake names, fake IC numbers, fake phone numbers. Never real customer or staff lists.
    
        
    Company accounts onlyNever build on a personal GitHub, Supabase, Vercel or similar account.
    
        
    Ask before connectingSending emails, reading Google Sheets or linking another system needs IT's OK first. Claude will flag it and carry on with the rest.
    
        
    When unsure, askA short delay is cheaper than a data leak. Claude writes open questions down instead of guessing.
    
      
    
    
    

    
    
      
    If something goes wrong
    
      
    
        
    
          
    What you seeWhat to do
    
          
            
    No preview link after 10 minutesTell Claude. It reads the error and fixes it. If it's stuck, ask IT.
    
            
    The preview shows a blank pageTell Claude what you see and what you expected.
    
            
    "Can't load data"The test database may be asleep. Ask IT to wake it up.
    
            
    "You don't have access yet"You haven't been given access to this app. Ask IT.
    
            
    Claude keeps breaking other partsAsk for one change at a time. If the chat has grown very long, start a new one.
    
            
    The live app is brokenContact a Reviewer right away. They can undo the last release in one click.
    
              
        
    
      
    
    
    

    
    
      Words you'll hear
      
    
        
    GitHub
    The company's safe for code, where every version is kept.
    
        
    Branch
    A private copy where changes are made safely.
    
        
    Save point (commit)
    A record of one change. You can always go back to it.
    
        
    Pull request
    A request to move your changes into the live app.
    
        
    Preview link
    A test web address with your changes only.
    
        
    Merge
    Accepting the pull request, so the change goes live. Only a Reviewer does this.
    
        
    Database
    Where the app saves its data, like an Excel sheet that updates itself.
    
        
    Staff login
    The company login page. IT decides who can use each app.
    
        
    Design kit
    The company's standard look, so every app has the same buttons, colours and tables.
